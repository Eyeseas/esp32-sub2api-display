# 屏幕界面与面板调校

记录日期：2026-10-04，2026-10-05 更新（Asia/Shanghai）。本文汇总 UI v2 的设计与实现、屏幕刷新方式，以及文字残影问题的排查和修正。板卡官方资料见[立创·实战派 ESP32-S3 Wiki](https://wiki.lckfb.com/zh-hans/szpi-esp32s3/)，接入和升级流程见[设备信息与接入手册](device-and-onboarding.md)。硬件为立创·实战派 ESP32-S3：2.0 寸 IPS、ST7789、320×240、SPI。

2026-10-06 起开机进入桌面（UI v3 方案 B 卡片轮播，见第 7 节），下面第 1 节的页面成为桌面上的 Sub2API 模块。

## 1. UI v2（方案 A：一屏全景）

可交互原型在 `prototypes/ui-v2/index.html`，其中 B、C 两个方案保留作对比。原型需要在仓库根目录用 http 服务打开，因为页面直接加载固件使用的字体：

```sh
python3 -m http.server 8790   # 浏览器打开 http://127.0.0.1:8790/prototypes/ui-v2/index.html
```

固件实现位于 `firmware/main/ui.c`，坐标与原型一致（按文字基线定位）。

| 页面 | 内容 | 操作 |
| --- | --- | --- |
| Sub2API 首页 | 状态栏最左为返回箭头，点状态栏或在第 1 页右滑回到桌面；状态栏（健康 X/Y、告警数、连接与数据新鲜度）；今日摘要（账号费用、请求、Token）；每页 3 个账号，每行并排显示前两个额度窗口及倒计时；页脚分页点 | 点今日摘要进入今日详情；点账号行进入详情；左右滑动或点页脚两侧翻页 |
| 今日详情 | 账号费用、请求、Token；模型分布（对应 sub2api 用量页的“模型分布”，按 Token 排序；横条是各模型的 Token 占比，每行显示请求、Token、账号费用；超过四个模型时第三行之后合并为“其余 N 个”；查询不完整时显示“模型数据不完整”） | 点顶部或右滑返回 |
| 账号详情 | 最多两个窗口（百分比、进度条、倒计时、数据质量，以及窗口开始至今的“请求 · Token · 账号费用”）；并发格；该账号今日用量；平台或未显示窗口数 | 点顶部或右滑返回 |

按键：单击用户按键（GPIO0）熄屏或亮屏。熄屏关闭背光并暂停绘制，联网刷新照常进行，亮屏时先画出最新数据、传输完成后再点亮背光；熄屏时触摸任意位置也能亮屏，这一下触摸不会点到下面的页面。

显示规则：

- 颜色只表示状态：绿色正常，琥珀色达到 80% 或限流类标记，红色达到 95% 或错误类标记，灰色表示过期、待新样本或未知。
- 快照超过 120 秒未更新时，整屏数值改为灰色。
- 倒计时在 10 分钟内精确到秒。
- 同一账号有多个标记时只显示最严重的一个，"额度提醒"让位于同级的其他标记。
- 滑动手势调用 `lv_indev_wait_release()`，因此滑动不会同时点开起点所在的账号行。
- USB `view` 命令：0 Sub2API 首页、1 今日详情、2 当前页第一个账号的详情；2026-10-06 起增加 3 桌面、4 系统信息。

数据与字库：

- `model.c` 新增解析每账号的 `today`（为 null 时显示 `--`）和 `type`，并计算标记严重度；2026-10-05 起还解析窗口的 `stats` 和今日的 `models`（含 `models_complete`）。
- 新增 Montserrat 12/16/40（LVGL 内置）和中文 14px 子集 `display_font_14.c`。
- `scripts/generate_font.py` 会从源码中自动收集汉字和 `·`，同时生成 16px 和 14px 两套中文子集。

## 2. 屏幕刷新方式

2026-10-05 起改为保留式渲染（提交 d4743fd）：

- 每次 `render()` 按固定顺序调用同一组绘制函数。同一位置、同一类型的对象会被复用，只写入变化了的属性（文字、颜色、位置、隐藏状态），LVGL 只重绘这些对象所在的区域。切换页面时调用序列不同，从第一个不匹配的位置起删除旧对象，剩余未用到的对象由 `trim()` 删除。
- 数据刷新不再删除重建对象，所以不会删掉手指正按着的账号行。
- 页面切换通过 `lv_async_call` 在 LVGL 任务中执行 `render()`；每秒的定时器只更新倒计时和连接时长，严重度或过期状态变化时才整页重新 `render()`。
- LVGL 以局部模式渲染，使用两块 320×40 的 DMA 缓冲：CPU 画一条，SPI DMA 送一条。
- 熄屏时跳过绘制；亮屏时 `render()` 后整屏作废重绘，`LV_EVENT_REFR_READY` 之后才点亮背光。
- 构建配置：`-O2`、CPU 240 MHz、32 KB 指令缓存、64 KB 数据缓存、QIO Flash（见 `sdkconfig.defaults`）。LVGL 从 Flash 执行，原先 16 KB 指令缓存加 DIO Flash 时缓存抖动严重。实测首页完整重建并重绘约 380 ms → 82 ms，普通数据刷新约 10 ms。
- SPI 80 MHz，无 TE 同步。

残影排查（第 3 节）发生在改版之前：当时 `render()` 每次先 `lv_obj_clean(body)`，而 `body` 铺满全屏，所以**每次切换都会作废并重写全部 76800 个像素**，旧画面不可能残留在显存里，页面切换后看到的旧字只能来自面板本身。这个结论不受之后的渲染方式改动影响。

## 3. 文字残影：原因与修正

### 现象

- 切换页面、甚至设备复位后，背景中仍能看到上一屏的文字。
- 照片中 #0b0e0d 背景显示为中灰；#242c28 的 1px 分隔线显示为亮白；白字外圈有一圈比背景还暗的轮廓。

### 用测试图定位

`display_test ramp` 绕过 LVGL 直接写屏，从上到下依次为：灰阶 0–255、暗部灰阶 0–60、红、绿、蓝色阶（各 16 级），以及界面色板加黑底 1px 白线。默认初始化下的测试结果：

1. 纯黑显示为中灰，灰阶在值 34 左右就接近全白；
2. 红、绿、蓝三条最左格都是纯黑，却分别显示成暗红、暗绿、暗蓝，说明同一行的内容会影响像素亮度（串扰）；
3. 色板中 #242c28 比 #4b5550 更亮，灰度不再单调；
4. 全屏重写后旧字仍然可见。

### 原因

固件和立创官方例程一样，只调用 esp_lcd 的默认初始化（SLPOUT、MADCTL、COLMOD、RAMCTRL），不写 VCOM、Gamma 和电源寄存器，屏幕运行在 ST7789 芯片的复位默认值上。立创文档没有提供这块屏的调校参数（见[液晶显示教程](https://wiki.lckfb.com/zh-hans/szpi-esp32s3/beginner/lcd-display.html)），默认值不适合这块面板。根据上面的现象推断，VCOM 偏置不当使黑色像素两端始终带有电压，因而发灰，并在液晶中积累电荷形成残影。

### 修正

`board_init()` 在打开显示之前写入：

| 寄存器 | 值 | 作用 |
| --- | --- | --- |
| C2 | 01 | 由寄存器设定 VDV/VRH |
| C3 | 12 | VRH，Gamma 参考电压 |
| C4 | 20 | VDV |
| BB | 19 | VCOM，约 0.725 V（芯片默认 0x20） |
| E0 | D0 04 0D 11 13 2B 3F 54 4C 18 0D 0B 1F 23 | 正极 Gamma |
| E1 | D0 04 0C 11 13 2C 3F 44 51 2F 1F 1F 20 23 | 负极 Gamma |

实时写入后的测试图：灰阶逐级可分，暗部可分辨，三原色条的黑格接近黑色，色板恢复单调，用户目测看不到旧字。这组值取自常见 2.0 寸 IPS 模块的初始化序列，**不是这块屏厂商提供的参数**。如果以后拿到屏模组的规格书或厂商初始化代码，应拿来替换对比。BB 也可以在 0x15–0x1D 之间继续微调。

## 4. 诊断工具

`scripts/display-test.py` 的所有步骤都在**同一次串口连接**里依次执行：

```sh
PY=.tools/idf-tools/python_env/idf6.1_py3.12_env/bin/python
$PY scripts/display-test.py --port /dev/cu.usbmodemXXXX --pattern ramp
$PY scripts/display-test.py --port /dev/cu.usbmodemXXXX --pattern ramp --register 0xBB 0x15
```

- `--pattern`：`black`、`gray`、`white`、`red`、`green`、`blue`、`ramp`、`flicker`、`off`、`ui`、`touch`。
- `--register CMD [DATA...]`：可重复，实时写面板寄存器，只接受 Gamma、电压和反色类寄存器（20、21、26、B7、BB、C0、C2–C6、D0、E0、E1）。写入的值复位后失效；确认后需要写进 `board_init()`。
- `flicker`：VCOM 闪烁测试图。亮、暗像素交错排列，覆盖 ST7789 可能使用的几种反转方式（像素点反转、子像素点反转、行/列反转各占一块）。VCOM 偏离中心时，对应区域会以半帧率闪烁。`--level` 设置亮像素灰度，默认 0x80。
- `--vcom-sweep BYTE...`：先把 C6 帧率降到 `--frame-rate`（默认 0x1F，约 39 Hz，闪烁更容易看出），再依次写入各 BB 值并显示 `flicker`，顶部格子标出当前档位（最多 32 档）。每档停留 `--hold` 秒（默认 6），共扫 `--rounds` 轮（默认 2）。闪烁最弱的一档就是 VCOM 的较优值。

```sh
$PY scripts/display-test.py --port /dev/cu.usbmodemXXXX --vcom-sweep 0x13 0x15 0x17 0x19 0x1B 0x1D
```
- 图案显示后保持不变，直到下一次打开串口。

**注意：在 macOS 上打开 ESP32-S3 的 USB 串口会复位开发板。** 包括 `device-check.py`、只读日志，以及每一次 `display-test.py` 调用。分多次调用时，前一次写入的寄存器和测试图都会丢失，所以调参必须把图案和所有寄存器放在同一条命令里。

SPI 时钟可在 `menuconfig → Display board → LCD SPI clock` 中调整，默认 80 MHz，与立创文档一致。

## 6. 背光 PWM

GPIO42 背光原先作为普通 GPIO 只有开、关两档，现在改为与立创例程相同的 LEDC PWM：低速模式、定时器 1、5 kHz、10 位分辨率，输出反相（背光低电平点亮）。

- 上电时占空比为 0，首帧传输完成后才按设定亮度点亮；`display_test` 熄灭和点亮背光的流程不变。
- 亮度范围 1–100%，保存在 NVS（命名空间 `display`，键 `backlight`），默认 100%。因为打开 USB 串口会复位开发板，亮度必须保存，否则下次连接就会丢失。
- 设置方法：

```sh
$PY scripts/display-test.py --port /dev/cu.usbmodemXXXX --backlight 40
```

USB 原始命令为 `{"command":"backlight","level":40}`，成功时回复 `BACKLIGHT_OK 40`。

已验证：构建与烧录通过，启动日志显示 `backlight PWM 100%`，`device-check.py` 收到 3 次快照、无崩溃，设备确认 40% 设置成功。各档亮度的实际观感和 PWM 是否可见闪烁，仍需用户目测。

## 7. 桌面与一言（UI v3 方案 B：卡片轮播）

记录日期：2026-10-06。原型在 `prototypes/ui-v3-home/index.html`（打开方式同 UI v2），A、C、D 三个方案保留作对比。最初实现的是方案 C（左侧图标栏 + 时钟 + 一言），当天改为方案 B。固件实现为 `ui.c` 的 `render_desk()` 和 `render_system()`。

桌面顶部 24px 是日期、星期和 Wi-Fi；下面是竖排的 272×168 卡片（x 32–304），一次居中一张，上下各露出相邻卡片 16px；左侧 x 14 是竖排的位置点。只有已经实现的模块才有卡片，计时器等不显示，也不放占位。

| 卡片 | 内容 | 点按 |
| --- | --- | --- |
| 时钟 + 一言（第 1 张，开机默认） | 时间（Montserrat 40 + 秒）、一言分类；分割线下最多 3 行一言（16px，行距 24px）和“—— 作者「出处」” | 换一句 |
| Sub2API 监控 | 正常 X/Y 与告警数、今日账号费用（40px）、请求数和 Token；当前页前 3 个账号各显示最紧的一个额度窗口（先比严重程度，再比用量）和进度条 | 进入 Sub2API 模块 |
| 系统信息 | 运行时长、Wi-Fi 名称与信号（或连接状态）、内部 RAM、PSRAM、固件版本 | 进入系统信息页 |

- 卡片在 LVGL 纵向滚动容器里，开启 `LV_SCROLL_SNAP_CENTER` 和 `LV_OBJ_FLAG_SCROLL_ONE`：上下拖动时卡片跟手，松开后吸附到中间，一次最多移动一张。点上下露出的卡片会把它滚到中间，而不是直接进入。
- 最初按原型做成左右滑动，实物上不好用，当天改为上下滑动。屏幕左边缘触摸不准（第 8 节），所以左侧一列只放位置点，不需要在那里操作。
- 停在时钟卡片时顶部不再重复时间；滑到其他卡片后，顶部左侧补上 `HH:MM`。从模块返回时停在进入前的那张卡片。
- 卡片容器沿用保留式渲染：每秒刷新只改变化的文字，不会打断正在进行的拖动。

- 时间按 sub2api 的时区显示：bridge 快照里的 `day.start_at` 是 `day.date` 当地零点对应的 UTC 时间，两者之差就是 UTC 偏移（`model.c`）。固件自身的 `TZ` 仍是 UTC。收到第一份快照之前显示 `--:--`。
- 模块内点顶部或右滑回到桌面；Sub2API 模块只在第 1 页右滑时返回桌面，其他页右滑仍是翻页。
- 系统信息页：Wi-Fi（SSID 与信号）、IP、运行时长、内部 RAM 与 PSRAM 可用量、固件版本与 IDF 版本，每秒刷新；最下面一行是触摸工具：“画板”（涂抹测试哪些位置能点到，按用户键返回系统信息页）和“校准”（第 8 节）。

一言：

- 设备直接请求 `https://v1.hitokoto.cn/?c=d&c=h&c=i&c=k&max_length=40`（文学、影视、诗词、哲学，避开动画类常见的日文），在 bridge 快照请求之后进行，同一时间只有一条 TLS 连接。成功后 10 分钟换一句，失败 60 秒后重试；点按会立即唤醒网络任务。接口限 2 QPS，连续请求间隔 600 ms。
- 实测一次请求约 5.7 秒，主要是 TLS 握手。失败时保留上一句；开机后、拿到第一句之前显示内置的“人生如逆旅，我亦是行人。”。
- v1.hitokoto.cn 发送的 GTS Root R4 由 GlobalSign Root CA 交叉签名，而 IDF 证书包已不含 GlobalSign Root CA，第一次实机请求因此证书校验失败。`sdkconfig.defaults` 开启了 `CONFIG_MBEDTLS_CERTIFICATE_BUNDLE_CROSS_SIGNED_VERIFY`，改为通过证书包里的 GTS Root R4 建立信任（约多用 700 字节堆）。

字库：

- 16px 中文字库 `display_font.c` 改为 GB2312 全集（6763 个汉字及其中的符号、假名，另补 U+2014、U+2013、U+00B7），共 7448 个字符，约 0.92 MB Flash；14px 仍是源码用字的子集。`scripts/generate_font.py` 同时生成两者。
- 句子或署名中只要有一个字不在 16px 字库里（`ui_text_supported()`），就跳过这一句再请求，每轮最多 4 次。
- 固件由 1.50 MB 增至 2.41 MB，4 MB app 分区剩余 40%。位图约 840 KB，低于 LVGL 未开 `LV_FONT_FMT_TXT_LARGE` 时单个字体 1 MB 的上限；以后若加大字号或换成更大的字符集，需要开启该选项。

已验证（2026-10-06）：构建无新警告；烧录后 `device-check.py` 显示已配置、3 个视图命令有回复、收到快照、无崩溃；串口日志 `quote accepted: attempt=1`，快照仍每 15 秒刷新。方案 B 固件 2.43 MB，改为上下滑动后启动、快照和一言均正常。卡片轮播在实物上的观感、上下滑动吸附的手感和点按，仍需用户目测确认。

## 8. 触摸校准

记录日期：2026-10-06。

### 现象与定位

桌面侧栏点房子会随机跳到 Sub2API、系统信息或计时器。临时给触摸读取加日志后，把每次触点按固件的点击区域重放，结果与设备实际触发的点击完全一致：跳转逻辑没有问题，是触摸上报的坐标偏了。用十字靶对照测得（实际 → 上报）：

| 位置 | 实际 | 上报 |
| --- | --- | --- |
| 左上 | (30, 30) | 约 (50, 65–92) |
| 左中 | (30, 120) | 约 (48, 163) |
| 左下 | (30, 210) | 约 (46, 226–239) |
| 中心 | (160, 120) | 约 (163, 110) |
| 右列 | (290, 30/120/210) | 约 (287, 13 / 119 / 217) |

中间和右列基本准，左列横坐标被压到 40 以上，纵坐标整体下偏约 40 px，而且随位置变化，不是一个统一的平移或缩放，改 `CONFIG_DISPLAY_TOUCH_*` 的交换和镜像解决不了。这是面板本身的线性度问题；驱动（esp_lcd_touch_ft5x06）和 esp_lvgl_port 只是原样转发坐标。侧栏紧贴左边缘、每格 48 px，所以点房子会落到下面的格子。

### 校准

- `board.c` 在 esp_lvgl_port 的读取回调外包一层：按下时把控制器坐标代入二次多项式（项为 1、u、v、uv、u²、v²，u = x/320，v = y/240），每个轴 6 个系数，结果限制在屏幕范围内。松开时 LVGL 沿用最后一次按下的坐标，所以只校正按下的采样。没有校准数据时坐标原样使用。
- 校准画面依次显示 3×3 共 9 个十字（x 30/160/290，y 30/120/210），当前目标为橙色，每个点 3 下。离目标超过 90 px 的点按视为误触，不计入。每个目标取 3 下的平均值，用最小二乘拟合（高斯消元解正规方程）；9 个目标中误差最大的超过 15 px 就拒绝并从头再来，否则把系数写入 NVS（命名空间 `display`，键 `touch_cal`，12 个 float）。之后进入检查模式，红点显示校正后的位置，点“完成”返回。
- 入口：系统信息页最下面一行的“校准”，或 USB 命令 `{"command":"display_test","pattern":"touch"}`（`display-test.py --pattern touch`）。与其他测试图一样，打开串口会复位开发板，所以用脚本时要在同一次连接里发命令并读取日志。
- 日志：每次计入的点按为 `touch: target N raw x= y=`；结果为 `touch: calibration ESP_OK, worst target X px` 和两行系数；启动日志的 board 一行末尾显示 `touch calibrated` 或 `touch uncalibrated`。

### 结果

2026-10-06 实机校准：9 个目标中误差最大 6.9 px。用这组系数重新换算之前被误判的点按：原本落到 Sub2API 的 (49, 65)、(50, 70) 等变为 y 20–39，即房子一格；左上角的返回点按落在顶部返回区。左列触点的纵坐标在上报值 240 处饱和，换算后最多到 y≈209，左下角最底下约 30 px 无法区分，但仍在侧栏“更多”一格之内。校准后侧栏和返回的实际手感，仍需用户确认。
