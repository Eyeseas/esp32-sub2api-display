# 实施与验收记录

最后验证：2026-10-04（Asia/Shanghai）。当前交付包含独立 bridge、ESP32-S3 固件、USB 配置工具和浏览器预览；没有修改 sub2api 源码。

已完成的功能包括：

- bridge 通过现有管理 API 定时采集账号状态、今日统计和保存额度，发布带设备 Token、范围过滤、ETag/304、分页和详情的缓存快照。
- 固件保存 Wi-Fi、bridge 地址和设备 Token 到 NVS，使用 HTTPS 证书包校验、SNTP 校时、断线重试和 32 KiB 响应上限。
- 三个 LVGL 视图（总览、额度、今日）、额度详情、窗口翻页和 USB `view` 命令已经接入。
- 2026-10-04 起屏幕改为 UI v2 方案 A（原型见 `prototypes/ui-v2/index.html`）：取消底部 Tab，首页同时显示健康、今日摘要和每账号前两个额度窗口；点今日摘要进入今日详情，点账号行进入详情，左右滑动翻页。新增 Montserrat 12/16/40 与中文 14px 字库。
- 2026-10-06 起开机进入桌面（UI v3 方案 B，原型见 `prototypes/ui-v3-home/index.html`）：卡片轮播，首张为时钟和一言，之后每个模块一张卡片；Sub2API 页面成为其中一个模块，另有系统信息页。16px 中文字库改为 GB2312 全集，设备直接请求一言。详见 `docs/display-ui-and-panel.md` 第 7 节。
- LCKFB 板级参数采用已验证的旧项目：I²C GPIO1/2、PCA9557 0x19、SPI3 mode 2、MOSI40/SCLK41/DC39、80 MHz、GPIO42 低电平背光、FT6336/FT5x06 0x38。

验证结果：

| 检查 | 结果 |
| --- | --- |
| `python3 -m unittest discover -s tests -v` | 16 项通过 |
| `scripts/idf.sh build` | ESP-IDF 6.1 构建通过，应用占用约 0x15f580，分区余量 66% |
| `node scripts/preview-check.mjs` | 真实 bridge 快照 3 个账号、`partial=false`，总览/额度/今日截图均生成 |

早期烧录发现配置路径会触发 FreeRTOS 调度器崩溃。原因是 `device_config_load()` 在主任务栈上放置 4096 字节 JSON 缓冲区，而 ESP-IDF 默认主任务栈只有 3584 字节；修复为堆分配并将项目主任务栈设置为 8192 字节。该修复后的固件已重新烧录并通过上述实机检查。

当前自动化日志能确认驱动初始化、Wi-Fi、网络快照和 USB 视图路径；由于本次无法现场查看屏幕，仍需之后人工确认屏幕方向、颜色和 FT6336 实际触摸坐标。浏览器预览已覆盖三个视图的视觉布局。

后续用户反馈：完全断电几分钟后开机仍有文字残影。已增加 USB 纯色诊断入口，直接覆盖 LCD 全部像素，并提供带人工观察结果的 `scripts/display-hitl.sh`。灰屏全屏填充后，用户反馈旧文字消失、屏幕呈白色；重新点亮并直接填充红色后，用户明确确认“全屏红色，没有旧文字”。该实物结果证明面板能正确更新纯红色画面，目前没有依据认定永久烧屏，也不能据此断言初始残影的唯一原因。

检查发现一个确定的初始化顺序缺陷：LCD CS 在软件复位之后才拉低，因此没有独立复位 GPIO 的 ST7789 无法接收到该复位命令。现已改为先拉低 CS 再复位，并保持 LCD 与背光关闭，直到 LVGL 完整绘制和 SPI DMA 传输完成后再显示首帧；根页面显式设置为完全不透明。LCD 的 SPI 模式、频率、RGB565 字节顺序和颜色反转设置沿用纯红色实物测试通过时的参数。

修正版本 `scripts/idf.sh build` 已通过，应用大小为 `0x160000`，4 MiB 应用分区余量为 66%。纯红色诊断的人工回复晚于脚本的 60 秒观察窗口，自动记录保持 `pending`，另在忽略的 `artifacts/display-diagnostic.json` 中记录用户的原文观察；没有把串口回包或超时脚本当作视觉验收通过。恢复应用界面后的背景颜色与残影仍需以实物反馈确认。

UI v2 与面板残影（2026-10-04）：屏幕改为 UI v2 方案 A；文字残影查明为 ST7789 复位默认的电压和 Gamma 不适合这块面板，`board_init()` 已写入经测试图验证的参数。设计、刷新机制、排查过程、诊断工具与待办见[屏幕界面与面板调校](display-ui-and-panel.md)。

## 实物验证记录（2026-10-04 至 2026-10-06）

- 2026-10-04：ST7789 默认的电压和 Gamma 设置造成背景发灰和文字残影；写入调校参数后，用户目测测试图已正常。修正了 LCD CS 拉低与软件复位的先后顺序，并改为首帧传输完成后才点亮背光。背光改为 PWM 调光。排查过程见[屏幕界面与面板调校](display-ui-and-panel.md)。
- 2026-10-05：改为保留式 LVGL 渲染，并调整构建配置（240 MHz、QIO、缓存、`-O2`）。实测首页完整重建并重绘的时间从约 380 ms 降到约 82 ms，数据刷新约 10 ms。
- 2026-10-06：开机改为桌面（侧栏 + 时钟 + 一言），16px 中文字库改为 GB2312 全集，固件 2.41 MB。一言首次实机请求因交叉签名证书校验失败，开启 `CROSS_SIGNED_VERIFY` 后正常。详见[屏幕界面与面板调校](display-ui-and-panel.md)第 7 节。
- 2026-10-06：触摸屏左边缘严重不线性（左上角偏差可达 50 px），导致侧栏点击乱跳。新增 9 点触摸校准，结果存 NVS，实测拟合误差最大 6.9 px。详见[屏幕界面与面板调校](display-ui-and-panel.md)第 8 节。
- 2026-10-06：桌面改为 UI v3 方案 B（卡片轮播，首张为时钟 + 一言），去掉计时器等占位模块；画板入口移到系统信息页底部。固件 2.43 MB。左右滑动在实物上不好用，随后改为上下滑动，位置点放在左侧。
- 待用户在实物上确认：卡片轮播的观感、上下滑动吸附和点按换句，以及触摸和滑动的手感、各档亮度的观感，以及之前积累的残影是否已完全消退。
